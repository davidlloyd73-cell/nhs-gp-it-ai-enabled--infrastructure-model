This maps an architecture designed and ready for deployment at one NHS GP practice (Ridgeway, Harrow). Some components are in daily clinical use (e.g. the Tortus scribe); the local inference layer is specified and awaiting hardware, not yet running — each node carries its own status. By design, identifiable inference will run locally and only synthetic, structured material crosses the boundary diode to the cloud assurance layer. Click any node for what it does, its data classification, status, and the repo or system that implements it.

Clinically-governed shared record (patient vault)

The longitudinal record. Patient is primary rights-holder; clinical systems are licensees of scoped, time-limited access. Proposed custodian: a regulated UK trust (working name “NHS Digital Identity Trust”) — not yet an existing body.
↓ scoped access for an episode of care
On-premise sees identifiable data

Local clinical inference & workflow

Mac mini M4 · Qwen 2.5 32B (Ollama / AnythingLLM) — hardware on order, not yet running — alongside best-of-breed modular apps. By design: air-gapped during clinical operation, clinician retains medico-legal responsibility.
↓ boundary diode — outbound: synthetic outputs · metrics · model hashes only
Safety-critical

Boundary diode

Unidirectional policy gateway. No patient text, transcript, prompt or output crosses outward. De-identification, allow-list enforcement, signed inbound templates, tamper-evident audit export.
↓ synthetic & structured only
Cloud never sees patient data

Cloud assurance harness

Validates, benchmarks and monitors the local model using synthetic cases, public vignettes and MRCGP-style material. Four-layer evaluation stack feeding the clinical safety case.
